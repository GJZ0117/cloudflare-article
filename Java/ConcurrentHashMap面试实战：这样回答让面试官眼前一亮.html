一、基础概念篇：必须掌握的面试题

问题1：HashMap为什么线程不安全？

普通回答： "HashMap在多线程下会出问题。"

高手回答： "HashMap在并发环境下存在三个核心问题：

  1. 死循环：JDK1.7扩容时可能形成环形链表，导致CPU 100%
  2. 数据丢失：多线程同时put，后写入的覆盖先写入的
  3. size不准：非原子操作导致计数错误

比如这个代码就会出问题：

// 危险代码：多线程环境下使用HashMap
Map<String, Integer> map = new HashMap<>();
ExecutorService executor = Executors.newFixedThreadPool(10);

for (int i = 0; i < 1000; i++) {
    final int index = i;
    executor.submit(() -> {
        map.put("key" + index, index); // 可能数据丢失或死循环
    });
}

面试技巧：结合具体问题场景，展示你的实践经验。

问题2：ConcurrentHashMap如何保证线程安全？

普通回答： "它用了锁机制。"

高手回答： "ConcurrentHashMap的线程安全设计经历了两次重大演进：

JDK1.7：分段锁机制

  • 将整个数组分成16个Segment，每个Segment独立加锁
  • 不同Segment的操作可以并行执行
  • 读操作基本不需要加锁

JDK1.8：CAS + synchronized

  • 锁粒度更细，只锁单个桶（链表头节点）
  • 读操作完全无锁，通过volatile保证可见性
  • 写操作只在哈希冲突时加锁

这种演进让并发性能提升了数倍！"

面试技巧：展示技术演进的理解，体现你的技术视野。

二、源码原理篇：展示你的技术深度

问题3：能详细说说put方法的流程吗？

普通回答： "就是先算hash，再放数据。"

高手回答： "put方法的流程很精妙，我画个流程图：

开始put
    ↓
参数校验（key/value不能为null）
    ↓
计算hash（(h ^ (h >>> 16)) & HASH_BITS）
    ↓
自旋开始 → 表未初始化？ → 执行初始化
    ↓
计算桶位置（(n-1) & hash）
    ↓
桶为空？ → CAS插入新节点 → 成功→跳出循环
    ↓
桶不为空
    ↓
正在扩容？ → 帮助扩容
    ↓
哈希冲突 → synchronized锁住桶头节点
    ↓
    ├─ 链表：遍历查找/插入
    ↓
    ├─ 红黑树：树节点操作
    ↓
检查树化条件（链表长度≥8 && 数组长度≥64）
    ↓
更新计数，检查扩容
    ↓
结束

关键点在于：

  • 使用CAS处理无竞争情况
  • synchronized只锁冲突的桶
  • 多线程协同扩容"

面试技巧：用流程图展示思维逻辑，让回答更清晰。

问题4：get方法为什么不需要加锁？

普通回答： "因为用了volatile。"

高手回答： "get方法无锁化的关键在于内存可见性的设计：

// 关键设计1：table数组volatile
transient volatile Node<K,V>[] table;

// 关键设计2：Node的val和next都是volatile
static class Node<K,V> {
    final int hash;
    final K key;
    volatile V val;        // 值volatile
    volatile Node<K,V> next; // 下一个节点volatile
}

// 关键设计3：安全发布机制
static final <K,V> Node<K,V> tabAt(Node<K,V>[] tab, int i) {
    return (Node<K,V>)U.getObjectVolatile(tab, ((long)i << ASHIFT) + ABASE);
}

这样设计的精妙之处在于：

  • 读操作看到的数据要么是完整的旧值，要么是完整的新值
  • 不会读到中间状态
  • 性能接近HashMap，但线程安全"

问题6：ConcurrentHashMap使用中遇到过什么问题？

普通回答： "没遇到过什么问题。"

高手回答（真实踩坑经验）： "我们踩过三个典型的坑：

坑1：错误使用导致内存泄漏

// ❌ 问题代码：会话管理内存泄漏
public class SessionManager {
    private ConcurrentHashMap<String, UserSession> sessions = new ConcurrentHashMap<>();
    
    public void addSession(UserSession session) {
        sessions.put(session.getId(), session);
        // 忘记清理过期会话，内存持续增长
    }
}

// ✅ 修复方案：定期清理 + 软引用
public class FixedSessionManager {
    private ConcurrentHashMap<String, SoftReference<UserSession>> sessions = new ConcurrentHashMap<>();
    
    public void addSession(UserSession session) {
        sessions.put(session.getId(), new SoftReference<>(session));
    }
    
    @Scheduled(fixedRate = 300000) // 5分钟清理一次
    public void cleanupExpiredSessions() {
        sessions.entrySet().removeIf(entry -> {
            SoftReference<UserSession> ref = entry.getValue();
            return ref == null || ref.get() == null || ref.get().isExpired();
        });
    }
}

坑2：复合操作的非原子性

// ❌ 问题代码：库存检查 then 扣减
public class InventoryService {
    private ConcurrentHashMap<Long, Integer> inventory = new ConcurrentHashMap<>();
    
    public boolean deductInventory(Long productId, int quantity) {
        // 这两步不是原子的！
        Integer stock = inventory.get(productId);
        if (stock != null && stock >= quantity) {
            inventory.put(productId, stock - quantity); // 可能被其他线程修改
            return true;
        }
        return false;
    }
}

// ✅ 修复方案：使用原子操作
public class FixedInventoryService {
    private ConcurrentHashMap<Long, AtomicInteger> inventory = new ConcurrentHashMap<>();
    
    public boolean deductInventory(Long productId, int quantity) {
        return inventory.computeIfPresent(productId, (k, v) -> {
            if (v.get() >= quantity) {
                return new AtomicInteger(v.get() - quantity);
            }
            return v; // 库存不足，不修改
        }) != null;
    }
    
    // 或者使用CAS风格
    public boolean safeDeductInventory(Long productId, int quantity) {
        AtomicInteger stock = inventory.get(productId);
        if (stock == null) return false;
        
        while (true) {
            int current = stock.get();
            if (current < quantity) return false;
            if (stock.compareAndSet(current, current - quantity)) {
                return true;
            }
            // CAS失败，重试
        }
    }
}

        if (isInactive(userId)) {
            userMap.remove(userId); // 可能抛ConcurrentModificationException
        }
    }

// ✅ 修复方案：安全删除
public void safeRemoveInactiveUsers() {
    // 方案1：使用迭代器
    Iterator<Map.Entry<String, User>> it = userMap.entrySet().iterator();
    while (it.hasNext()) {
        Map.Entry<String, User> entry = it.next();
        if (isInactive(entry.getKey())) {
            it.remove(); // 安全删除
        }
    }
    
    // 方案2：使用removeIf（更简洁）
    userMap.keySet().removeIf(this::isInactive);
}

// ✅ 正确：预估容量避免扩容

public class KeyDesign {

    public String goodKey(Long userId) {

五、场景设计：展示你的架构能力

问题8：如果用ConcurrentHashMap设计一个缓存系统？

高手回答（完整设计方案）： "我会设计一个包含多级过期、内存控制、监控告警的完整缓存系统：

@Component
public class SmartCache<K, V> {
    private final ConcurrentHashMap<K, CacheEntry<V>> cache = new ConcurrentHashMap<>();
    private final AtomicLong memoryUsage = new AtomicLong(0);
    
    // 缓存条目，包含过期时间
    private static class CacheEntry<V> {
        private final V value;
        private final long expireTime;
        private final long memorySize;
        
        CacheEntry(V value, long ttl, long memorySize) {
            this.value = value;
            this.expireTime = System.currentTimeMillis() + ttl;
            this.memorySize = memorySize;
        }
        
        boolean isExpired() {
            return System.currentTimeMillis() > expireTime;
        }
    }
    
    public V get(K key) {
        CacheEntry<V> entry = cache.get(key);
        if (entry == null) return null;
        
        // 惰性过期检查
        if (entry.isExpired()) {
            cache.remove(key);
            memoryUsage.addAndGet(-entry.memorySize);
            return null;
        }
        
        return entry.value;
    }
    
    public void put(K key, V value, long ttl) {
        // 内存控制：超过阈值先清理
        if (memoryUsage.get() > MAX_MEMORY) {
            cleanupExpiredEntries();
        }
        
        long memorySize = calculateMemorySize(value);
        CacheEntry<V> entry = new CacheEntry<>(value, ttl, memorySize);
        
        CacheEntry<V> oldEntry = cache.put(key, entry);
        if (oldEntry != null) {
            memoryUsage.addAndGet(-oldEntry.memorySize);
        }
        memoryUsage.addAndGet(memorySize);
    }
    
    // 定期清理过期条目
    @Scheduled(fixedRate = 300000) // 5分钟
    public void scheduledCleanup() {
        cleanupExpiredEntries();
    }
    
    private void cleanupExpiredEntries() {
        cache.entrySet().removeIf(entry -> {
            if (entry.getValue().isExpired()) {
                memoryUsage.addAndGet(-entry.getValue().memorySize);
                return true;
            }
            return false;
        });
    }
    
    // 监控接口
    public CacheStats getStats() {
        return new CacheStats(cache.size(), memoryUsage.get());
    }
}

这个设计解决了生产环境的四个核心问题：

  1. 内存控制：防止缓存撑爆内存
  2. 过期清理：定期+惰性双重清理
  3. 性能保障：基于ConcurrentHashMap的高性能
  4. 可观测性：提供监控指标"
